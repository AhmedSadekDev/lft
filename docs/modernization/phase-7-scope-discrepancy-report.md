## 2. تحليل الفجوات والتعارضات التقنية المكتشفة (Critical Discrepancies)

طبقًا للشرط الحازم في **بند 1 (Critical Scope Gate)**:  
> *"If Phase 7 is not explicitly defined, or if multiple incompatible definitions exist, do not invent a new phase or silently select a scope. Instead, produce a precise scope-discrepancy report, propose a clearly labeled Phase 7 scope for owner approval, and stop before implementation."*

تم رصد 3 فجوات جوهرية تتطلب قرار المالك قبل بدء التعديلات:

### الفجوة الأولى: إيجاز نص الخطة الأصلية (Lack of Detailed Deliverables in Section 10)
على عكس المراحل السابقة (مثل Phase 4B التي شملت 10 بنود تفصيلية وجدول جرد شاشات، أو Phase 5 التي حددت سياج الأمان المالي بالتفصيل)، وردت Phase 7 في السطور 257–262 من وثيقة الخطة في 3 نقاط عامة فقط:
1. *نقل إشعارات FCM، رسائل البريد الإلكتروني SMTP، وتوليد ملفات الـ PDF/Excel الكبيرة إلى طوابير العمل في الخلفية.*
2. *اعتماد سياسة الكاش الحذرة: حظر كاش الأرصدة المالية، وقصر الكاش على البيانات المرجعية شبه الثابتة مع Model Observers للتنظيف الفوري.*
3. *ضبط معالجة المرفقات وتوليد نسخ مصغرة (Thumbnails) لتسريع العرض الميداني والإداري.*

ولم يتم تحديد مصفوفة مسارات واضحة، ولا آلية التعامل مع التنزيل الفوري للملفات، ولا مصير القسم 11 (الأمان والتدقيق).

---

### الفجوة الثانية: التعارض الحرج بين متطلبات الـ Queue والسياسة الدائمة لقاعدة البيانات
1. **توصية الخطة وتقرير الفحص Phase 0 (بند RSK-03):** أوصت بالانتقال من `sync` إلى `database` أو `redis` queue driver.
2. **الفحص الفعلي لبيئة التشغيل:**
   - جدول `jobs` **غير موجود نهائيًا** في قاعدة بيانات `leader` التشغيلية (`Schema::hasTable('jobs') === false`).
   - جدول `cache` **غير موجود نهائيًا** في قاعدة بيانات `leader` (`Schema::hasTable('cache') === false`).
   - إضافة Redis غير مفعلة في PHP (`extension_loaded('redis') === false`).
   - الإعدادات الحالية: `QUEUE_CONNECTION=sync` و `CACHE_DRIVER=file`.
3. **التعارض الصارم مع سياسة قاعدة البيانات الدائمة (Permanent Database Policy):**
   - تنص السياسة صراحة على: *"Never run php artisan migrate... No table creation... Missing tables are LEGACY CODE / DATABASE MISMATCH"*.
   - تشغيل أمر إنشاء جداول الطوابير `php artisan queue:table` أو تشغيل أي migration يُعد **مخالفة صريحة ومباشرة لسياسة المالك الدائمة**.

**الخيارات المتاحة لحسم هذه الفجوة:**
* **الخيار (أ) - موصى به ومتوافق 100% مع السياسة:**
  - برمجة المهام كـ `ShouldQueue` Jobs معمارياً بحيث تكون جاهزة للعمل في الخلفية.
  - اختبارها وتشغيلها في بيئة الاختبارات المعزولة (SQLite / Test DB مع جدول jobs مستقل) لإثبات صحة الـ Dispatch والـ Retry والـ Idempotency.
  - إعداد ملف SQL مفصول للمراجعة `phase-7-queue-infrastructure.sql` لإنشاء جدول `jobs` و `failed_jobs` يدوياً إذا وافق المالك على تطبيقه على MySQL لاحقاً، مع بقاء البيئة الافتراضية على `sync` أو ملفات لحين الموافقة.
  - استخدام `CACHE_DRIVER=file` (النشط بالفعل) للكاش دون لمس قاعدة البيانات إطلاقاً.
* **الخيار (ب) - استثناء صريح من المالك:**
  - منح استثناء صريح من المالك لإنشاء جدول `jobs` عبر SQL مباشر على `leader` لدعم الطوابير في بيئة التطوير والتشغيل.

## 3. النطاق المقترح تفصيليًا للمرحلة السابعة (Proposed Phase 7 Scope for Owner Approval)

نقترح حصر وتنفيذ المرحلة السابعة بدقة في **4 محاور تنفيذية محكمة**:

### المحور الأول: طوابير العمل في الخلفية (Background Queues)
1. **طابور إشعارات الموبايل (FCM Push Notifications):**
   - حصر 12 استدعاءً مباشرًا لـ `SendNotification::send` في متحكمات المشرفين والمندوبين.
   - إنشاء وظيفة خلفية `SendPushNotificationJob` مع سياسة إعادة المحاولة (3 محاولات، exponential backoff، تسجيل الأخطاء).
   - توفير مفتاح خيار فوري (Async Dispatch) مع اختبارات آلية لإثبات خروج استدعاءات الـ HTTP من دورة طلبات الـ API.
2. **التقارير الثقيلة وتصدير البيانات:**
   - توفير مسار معالجة في الخلفية لتصديرات Excel الكبيرة دون تعليق الـ Web Worker.
3. **تسليم البنية التحتية للطوابير:**
   - تسليم ملف `docs/modernization/phase-7-queue-infrastructure.sql` لإنشاء جداول `jobs` و `failed_jobs` للمراجعة، واختبار كامل دورة العمليات في بيئة الاختبار المعزولة.

### المحور الثاني: الكاش الحذر وبيانات المراجع (Cautious Caching)
1. **سياج الأمان المالي (Zero Financial Cache Invariant):**
   - حظر قاطع لأي كاش على الأرصدة أو المحافظ أو الفواتير أو قيود الخزينة والبنوك.
2. **كاش القوائم المرجعية شبه الثابتة (Semi-Static Dictionaries):**
   - تطبيق الكاش على بيانات: الساحات (`Yard`)، التوكيلات الملاحية (`ShippingAgent`)، الفروع (`Branch`)، وإعدادات النظام.
   - استخدام `CACHE_DRIVER=file` دون الحاجة لأي جداول إضافية في قاعدة البيانات.
   - بناء Model Observers (`YardObserver`, `ShippingAgentObserver`, إلخ) لتفريغ الكاش فورًا (Bust on Save/Delete) لضمان عدم وجود بيانات قديمة.

### المحور الثالث: معالجة الوسائط وتوليد المصغرات (Media & Thumbnails)
1. **محرك مصغرات أصيل (Native GD Thumbnail Engine):**
   - بناء `ThumbnailService` باستخدام `ext-gd` دون تثبيت حزم خارجية جديدة.
   - توليد نسخ مصغرة (Thumbnails) بأبعاد مثالية (مثلاً 300×300) عند رفع صور الحاويات والإيصالات والمندوبين.
2. **التوافق الرجعي التام:**
   - إضافة دالة مساعدة / Accessor ذكية (`thumbnail_url`) تُرجع رابط المصغر إن وُجد، أو تعود للصورة الأصلية تلقائياً دون أي كسر لتطبيقات الموبايل أو لوحة التحكم.

### المحور الرابع: حزمة الاختبارات الشاملة والتوثيق
1. كتابة حزمة اختبارات مخصصة `tests/Feature/Phase7QueuesAndCachingTest.php`.
2. الحفاظ على الـ Baseline المعتمد: **125 اختباراً ناجحاً + اختبارات Phase 7 الجديدة، مع بقاء الـ 35 إخفاقاً التاريخية فقط وصفر إخفاقات جديدة**.
3. إصدار التقرير النهائي `docs/modernization/phase-7-completion-report.md`.
